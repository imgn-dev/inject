# Changelog

One section per release, newest first. Within a section, entries are listed in
the order the changes landed, each referencing its commits.

## Unreleased

- **Processor supports newer source versions.** `InjectProcessor` declared
  `RELEASE_21` as its supported source version, so javac warned on every build
  with a newer `-source`, and builds with `-Werror` failed. It now supports the
  running compiler's latest source version.
  ([eec1a1b](https://github.com/imgn-dev/inject/commit/eec1a1b))
- **Overloads no longer break generated factories.** A bean with another
  constructor, `@Inject` method or `@Provides` method of the same arity got a
  factory that did not compile ("reference to … is ambiguous"). Generated
  resolution calls now name the dependency type, so the injected overload is
  selected. At first resolution, a dependency whose value is not of the declared
  type, or `null` for a primitive, throws an `InjectionException` naming the
  injection point. **Breaking:** the `Factory` methods `getInstanceFor…` and
  `getProviderFor…` take the erased dependency type, as in
  `this.<Foo>getInstanceForConstructor(0, Foo.class, context)`; factories
  generated by the 0.1.0 processor must be regenerated.
  ([70f0d9c](https://github.com/imgn-dev/inject/commit/70f0d9c))
- **Builder bindings can supply concrete types; dependencies are checked at
  injector creation.** A concrete dependency with neither an `@Inject`
  constructor nor an accessible no-argument constructor was a compile error,
  even when `Injector.builder().bind(...)` supplied it. The processor now
  leaves it to the runtime, like an interface. In exchange, creating an
  injector checks that every bean's dependencies are bound and throws one
  `UnsatisfiedDependencyException` listing every missing one, instead of
  failing on the first resolution that needs it. **Breaking:** a dependency
  bound only in child injectors now also needs a root-level binding.
  ([b215bdb](https://github.com/imgn-dev/inject/commit/b215bdb))
- **The repository moved to `imgn-dev/inject`.** It is public at
  https://github.com/imgn-dev/inject; the POMs' URL and SCM point there.
  ([2a3bee2](https://github.com/imgn-dev/inject/commit/2a3bee2))
- **The processor builds on Gaia.** `inject-processor` uses `gaia-processing`
  instead of JavaPoet.
  - Generated sources are pure ASCII, and carry
    `@javax.annotation.processing.Generated` when the compilation can see it.
  - The factory service file lists its entries sorted, and fails the build if
    one cannot be loaded by `ServiceLoader`. On an incremental build it keeps
    the entries already in the class output, minus those whose class no longer
    exists.
  - A bean whose signature names a type another processor has not generated yet
    waits for the round that generates it.
  - A dependency compiled from source in any round gets a default factory,
    unless a binding from that round or an earlier one already serves it.
  - **Breaking:** `InjectPlugin.initializer` returns
    `Optional<be.imgn.gaia.processing.source.CodeBlock>`; processor plugins
    must move from JavaPoet to `gaia-processing`.
  ([04004a5](https://github.com/imgn-dev/inject/commit/04004a5))
- **Fewer unchecked-cast suppressions in interception proxies.** A proxy method
  carries `@SuppressWarnings("unchecked")` only when one of its casts is
  unchecked: a cast to a type whose arguments are all unbounded wildcards, such
  as `List<?>`, no longer gets it.
  ([9354e7e](https://github.com/imgn-dev/inject/commit/9354e7e))
- **Gaia 0.1.1.** `inject-processor` depends on `gaia-processing` 0.1.1;
  processor plugins build against that version.
  ([8fd5b19](https://github.com/imgn-dev/inject/commit/8fd5b19))
- **The processor is a module.** `inject-processor` is the module
  `be.imgn.inject.processor`, which provides
  `javax.annotation.processing.Processor`, so javac runs it from the processor
  module path as well as from the processor path. Plugins on the processor
  module path provide `InjectPlugin` in their descriptor.
  ([06534a8](https://github.com/imgn-dev/inject/commit/06534a8))
- **Gaia 0.1.2.** `inject-processor` depends on `gaia-processing` 0.1.2;
  processor plugins build against that version.
  ([97d804f](https://github.com/imgn-dev/inject/commit/97d804f))
- **Inherited scopes.** A bean class that declares no scope inherits the one
  its superclasses and superinterfaces declare, at any depth, also from class
  files; the nearest declaration wins along each path. Different scopes
  inherited along different paths are a compile error. A bean whose supertype
  another processor has yet to generate waits for a later round.
  ([c2e9352](https://github.com/imgn-dev/inject/commit/c2e9352))
- **Child-local scopes.** A scoping annotation with no `Scope` service is
  child-local, and `Injector.scopedChildBuilder(scope)` builds a child that
  hosts it: each bean of the scope is created once per hosting child, built
  through it, and cached there; the nearest host in the chain wins. Resolving
  such a bean with no host in the chain throws a `ScopeResolutionException`.
  A scoping annotation with no `Scope` service is no longer an error at
  injector creation. **Breaking** for `Injector` implementations: the
  interface has the new method `scopedChildBuilder`.
  ([974940e](https://github.com/imgn-dev/inject/commit/974940e))
- **Closing child injectors.** Closing an injector closes its live child
  injectors first, newest first, then runs `@PreDestroy` on its own instances
  in reverse creation order; for a child, those of the scope it hosts. Failures
  are handled as for the root: every instance is still destroyed, the first
  failure is thrown and the others are suppressed. After closing, `get()` on a
  `Provider` obtained through the injector fails too.
